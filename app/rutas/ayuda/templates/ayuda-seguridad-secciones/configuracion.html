Toda la configuración sensible está en el archivo .env de la raíz del proyecto.

El .env nunca se sube a git ni se comparte por chat o correo. Quien lo tiene, tiene acceso total a la base de datos.

Ver la configuración sin mostrar los secretos

Get-Content .env | ForEach-Object { if ($_ -match 'PASSWORD|SECRET|TOKEN') { ($_ -split '=',2)[0] + '=***' } else { $_ } }

Generar un valor aleatorio (contraseñas, SECRET_KEY)

$rng = [Security.Cryptography.RandomNumberGenerator]::Create(); $b = New-Object byte[] 32; $rng.GetBytes($b); -join ($b | ForEach-Object { $_.ToString('x2') })

Genera 64 caracteres hexadecimales: solo letras y números, sin problemas de comillas ni símbolos.

Aplicar un cambio del .env

docker restart no vuelve a leer el .env. Después de cambiarlo, siempre hay que recrear los contenedores:

docker compose -f dock/docker-compose.yml up -d

Si la variable la usa un solo servicio, alcanza con recrear ese: docker compose -f dock/docker-compose.yml up -d app.

En docker-compose.yml, las variables del .env llegan a los contenedores solo con env_file:. Escribir ${VAR} dentro de environment: deja el valor vacío, porque Compose no lee el .env de la raíz para eso.
