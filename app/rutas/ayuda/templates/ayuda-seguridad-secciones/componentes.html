Sysclin corre en contenedores Docker definidos en dock/docker-compose.yml. Cada contenedor cumple una sola función:

ContenedorFunciónAcceso desde la PCDentro de Docker
syscomcli_nginxEntrada oficial: HTTPS; redirige HTTP a HTTPShttps://localhost (443) y http://localhost (80)nginx
syscomcli_appAplicación web (Flask)http://localhost:5005 (directo, solo desarrollo)app:5000
syscomcli_bdBase de datos PostgreSQL 17localhost:5434db:5432
syscomcli_backupBackup automático cifrado cada 24 h——
debugpy (en syscomcli_app)Depurador remoto (solo desarrollo)localhost:5680app:5678
navegador ──HTTPS (443)──► nginx ──HTTP por la red interna──► app:5000 ──► db:5432
navegador ──HTTP (80)────► nginx ──► redirige a HTTPS
backup ──pg_dump (cada 24 h)──► db:5432 ──► backups/*.dump.gpg (cifrado)
  • Los usuarios entran por https://localhost (en el servidor, https://<dominio>).
  • El puerto 5005 es un acceso directo a Flask sin cifrar; existe solo para desarrollo y en el servidor queda cerrado.
  • Red interna: dock_network-tesis. La aplicación llega a la base por esa red (db:5432), no por el puerto 5434.
  • Datos: volumen Docker tesis_syscomcli_data. Detener, recrear o actualizar los contenedores no borra datos.
  • Backups: carpeta backups/ del proyecto.
  • Base de trabajo: sysclin_bd. La base clinicain es legado y no se usa.
  • Todos los contenedores tienen restart: always: si se caen o se reinicia Docker, vuelven a levantarse solos.
