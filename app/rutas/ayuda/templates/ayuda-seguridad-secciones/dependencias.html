• Las librerías de Python están en requirements.txt, cada una con su versión exacta. Solo se instalan las que el sistema usa.
  • La revisión se hace cada mes, antes de cada despliegue y cuando se agrega una librería.
  • Las imágenes base (python:3.12-slim, postgres:17, nginx:1.27-alpine) se actualizan junto con las dependencias.

1. Buscar vulnerabilidades conocidas

Corre en un contenedor temporal, sin tocar la app:

docker run --rm -v "${PWD}\requirements.txt:/r/requirements.txt:ro" python:3.12-slim sh -c "pip install -q --root-user-action=ignore --disable-pip-version-check pip-audit && pip-audit -r /r/requirements.txt --progress-spinner off"

Esperado: No known vulnerabilities found. Si aparece alguna, la columna Fix Versions indica la versión que la corrige.

2. Ver qué versiones nuevas hay

docker run --rm -v "${PWD}\requirements.txt:/r/requirements.txt:ro" python:3.12-slim sh -c "pip install -q --root-user-action=ignore --disable-pip-version-check -r /r/requirements.txt && pip list --outdated"

3. Actualizar

  1. Cambiar la versión en requirements.txt.
  2. Volver a correr el paso 1.
  3. Reconstruir la imagen y recrear la app (capítulo Contenedores). Corta el servicio unos 30 a 60 segundos.
  4. Probar: inicio de sesión, una pantalla de cada módulo, un PDF de factura y uno de reporte, y este manual en PDF.

Si una actualización de versión mayor (por ejemplo, de 4.x a 5.x) rompe algo, volver a la versión anterior y reconstruir. Si una vulnerabilidad no tiene corrección, documentarla como riesgo aceptado con su mitigación.

Antes de quitar una librería, confirmar que nada la importe:

Get-ChildItem app, run.py -Recurse -Include *.py | Select-String -Pattern "^\s*(import|from)\s+<modulo>\b"
