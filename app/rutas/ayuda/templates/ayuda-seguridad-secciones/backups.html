Política

AspectoPolítica
FrecuenciaAutomático cada 24 h (y uno apenas arranca el contenedor). Manual antes de cada migración, actualización o despliegue
Retención14 días; los más viejos se borran solos
CifradoGPG asimétrico. El servidor tiene solo la clave pública: puede cifrar, no descifrar. Nunca se genera un backup sin cifrar
CustodiaClave privada y su contraseña en poder del administrador, guardadas por separado, fuera del servidor
Prueba de restauraciónMensual, y antes de cada entrega o despliegue. Un backup que no se probó no se da por válido
Copia fuera del equipoRecomendada, semanal. Al estar cifrados, pueden guardarse en una nube sin exponer datos
Objetivo de recuperaciónPérdida máxima de 24 h de datos

Cómo funciona

             clave PÚBLICA (servidor)                 clave PRIVADA + contraseña (solo el administrador)
pg_dump ──► cifrar ──► backups/*.dump.gpg ───────────────► descifrar ──► restaurar
  • Archivo: backups/sysclin_bd_AAAAMMDD_HHMMSS.dump.gpg.
  • Clave pública: dock/backup/keys/backup_pub.asc. Aunque alguien se lleve el servidor, los backups son ilegibles.
  • Si falta la clave pública, el backup no se hace. El dump sin cifrar existe solo un instante dentro del contenedor y se borra siempre, salga bien o mal.
  • Los scripts son dock/backup/entrypoint.sh (ciclo cada 24 h) y dock/backup/backup.sh (la copia); ver el Anexo.

Custodia de la clave privada

ElementoDónde
Clave públicadock/backup/keys/backup_pub.asc. Se puede compartir
Clave privadabackup_privada.asc, en USB o gestor de contraseñas del administrador. Nunca en el servidor ni en el repositorio
Contraseña de la clave privadaGestor de contraseñas, separada del archivo
Huella de la clave vigente5CBD D0C3 C3A5 7281 CEE5 AF1B C0CE EFF6 A6B5 D972

Sin la clave privada y su contraseña, ningún backup se puede recuperar. Conviene tener dos copias de la clave privada en lugares distintos.

En los comandos siguientes, <ruta_clave_privada> es la ubicación del archivo (por ejemplo E:\backup_privada.asc en un USB).

Ver la huella de la clave pública instalada:

docker run --rm -v "${PWD}\dock\backup\keys\backup_pub.asc:/k/pub.asc:ro" postgres:17 bash -c "mkdir -m 700 /tmp/g && GNUPGHOME=/tmp/g gpg --show-keys --with-fingerprint /k/pub.asc"

Hacer un backup manual

docker exec syscomcli_backup sh /scripts/backup.sh

Termina con Backup creado: sysclin_bd_<fecha>.dump.gpg (<tamaño>) y la lista de backups.

# Listar los backups
Get-ChildItem backups | Select-Object Name, Length, LastWriteTime

# Ver los últimos backups automáticos y si hubo errores
docker logs syscomcli_backup --tail 20

# Copia fuera del equipo (por ejemplo, a un USB en E:)
Copy-Item backups\*.dump.gpg E:\sysclin_backups\

Prueba de restauración

Una vez por mes y antes de cada entrega o despliegue. La base real no se toca.

# El backup más reciente
docker run --rm -it --network dock_network-tesis --env-file .env -v "${PWD}\backups:/backups:ro" -v "${PWD}\dock\backup:/scripts:ro" -v "<ruta_clave_privada>:/clave/backup_privada.asc:ro" postgres:17 sh /scripts/restore_test.sh

# Un backup en particular: agregar su nombre al final
# ... postgres:17 sh /scripts/restore_test.sh sysclin_bd_<fecha>.dump.gpg

El script (dock/backup/restore_test.sh):

  1. pide la contraseña de la clave privada;
  2. descifra el backup;
  3. lo restaura en una base temporal (sysclin_restore_test);
  4. compara la cantidad de registros de usuarios, pacientes, citas, consultas, facturas y auditoria_sistema contra la base real;
  5. borra la base temporal y el archivo descifrado.

Resultado esperado: una tabla con las cantidades y RESTAURACION OK. Que "restaurada" sea menor que "actual" es normal: corresponde a lo cargado después del backup. Si dice RESTAURACION FALLO: <motivo>, el motivo indica el problema (no se encontró el backup, falta la clave, contraseña incorrecta o archivo dañado).

Restauración de emergencia

Solo si la base se dañó o se perdió. Reemplaza el contenido de sysclin_bd por el del backup elegido.

  1. Si la base todavía responde, hacer antes un backup del estado actual.
  2. Elegir el backup (listado de arriba).
  3. Detener la aplicación y el backup; la base queda corriendo: 
    docker compose -f dock/docker-compose.yml stop app backup
  4. Descifrar y restaurar (pide la contraseña de la clave): 
    docker run --rm -it --network dock_network-tesis --env-file .env -v "${PWD}\backups:/backups:ro" -v "<ruta_clave_privada>:/clave/k.asc:ro" postgres:17 bash -c 'mkdir -m 700 /tmp/g && export GNUPGHOME=/tmp/g && gpg --batch --quiet --import /clave/k.asc && gpg --pinentry-mode loopback --output /tmp/r.dump --decrypt /backups/<archivo>.dump.gpg && PGPASSWORD=$POSTGRES_PASSWORD pg_restore -h db -U $POSTGRES_USER -d $DB_NAME --clean --if-exists /tmp/r.dump'
  5. Volver a levantar: 
    docker compose -f dock/docker-compose.yml start app backup
  6. Comprobar que se puede iniciar sesión y que los datos están.

Los permisos de sysclin_app sobre las tablas vienen incluidos en el backup.

Si se pierde la clave privada

  • Los backups ya cifrados con esa clave no se pueden recuperar.
  • Generar enseguida un par de claves nuevo (abajo), hacer un backup manual y una prueba de restauración.

Generar un par de claves nuevo

Solo en una instalación nueva, o si se perdió o se comprometió la clave privada. Pide la contraseña de la clave dos veces.

$dir = "$env:USERPROFILE\sysclin_clave_backup"
New-Item -ItemType Directory -Force $dir | Out-Null
docker run --rm -it -v "${dir}:/clave" postgres:17 bash -c "mkdir -m 700 /tmp/g && export GNUPGHOME=/tmp/g && gpg --pinentry-mode loopback --quick-gen-key 'Sysclin Backup <backup@sysclin.local>' default default never && gpg --armor --export 'Sysclin Backup' > /clave/backup_pub.asc && gpg --pinentry-mode loopback --armor --export-secret-keys 'Sysclin Backup' > /clave/backup_privada.asc && gpg --list-keys"

# Instalar la pública y reiniciar el backup
Copy-Item "$dir\backup_pub.asc" dock\backup\keys\backup_pub.asc
docker restart syscomcli_backup
  1. Pasar backup_privada.asc a su lugar de custodia y borrarla de la PC.
  2. Anotar la huella nueva en la tabla de custodia.
  3. Hacer una prueba de restauración.

Conservar la clave privada anterior mientras existan backups cifrados con ella (14 días).
